# Demo-сценарий ContractFlow

Этот сценарий показывает основной пользовательский поток demo-версии ContractFlow.

Цель demo: показать, как система принимает реквизиты контрагента из Excel, проверяет их, импортирует в нормализованную модель PostgreSQL, создаёт договорный документ, генерирует файл и ведёт реестр статусов.

---

## 1. Запустить приложение

Перейдите в папку приложения:

```text
06_app
```

Запустите Streamlit:

```powershell
python -m streamlit run app.py
```

Откройте приложение в браузере:

```text
http://localhost:8501
```

---

## 2. Проверить подключение

В меню выберите:

```text
Проверка подключения
```

Ожидаемый результат:

```text
Подключение выполнено. База: contractflow_demo
```

---

## 3. Выбрать пользователя

В левой панели выберите demo-пользователя.

На текущем этапе demo-версии выбор пользователя работает без пароля. Это упрощённый режим для локального MVP.

Полноценная авторизация и ролевая модель могут быть добавлены на следующем этапе развития проекта.

---

## 4. Загрузить реквизиты контрагента

В меню выберите:

```text
Загрузка реквизитов
```

Загрузите demo Excel-файл:

```text
demo_files/demo_counterparty_requisites.xlsx
```

В файле может быть несколько листов, например:

```text
ООО
ИП
```

Выберите нужный лист.

Проверьте предпросмотр распознанных данных.

Нажмите:

```text
Загрузить в staging
```

Ожидаемый результат:

```text
Файл загружен в staging. Номер импорта: ...
```

---

## 5. Провалидировать и импортировать реквизиты

В меню выберите:

```text
Валидация и импорт реквизитов
```

Выберите нужный номер импорта.

Нажмите:

```text
Валидировать выбранный импорт
```

Если данные корректны, ожидаемый статус:

```text
Проверено
```

Если есть ошибки или предупреждения, они появятся в блоке:

```text
Ошибки и предупреждения
```

После успешной валидации нажмите:

```text
Импортировать реквизиты в core
```

Ожидаемый результат:

```text
Импорт перенесён в core
```

---

## 6. Проверить полноту контрагента

В меню выберите:

```text
Полнота контрагентов
```

Найдите загруженного контрагента.

Ожидаемый результат:

```text
Готов к договору = True
```

Если контрагент не готов к договору, в таблице будет указано, каких данных не хватает.

---

## 7. Создать договорный документ

В меню выберите:

```text
Создание документа
```

Выберите:

* наше demo-юрлицо;
* контрагента;
* тип документа;
* дату документа.

Для первого документа выберите тип:

```text
CONTRACT
```

Нажмите:

```text
Создать документ
```

Ожидаемый результат:

```text
Документ создан
```

Система автоматически:

* создаёт договорную связку;
* создаёт запись в `core.contract_documents`;
* генерирует номер документа;
* фиксирует подписантов;
* ставит первичный статус `GENERATED`.

---

## 8. Проверить очередь генерации

В меню выберите:

```text
Очередь генерации
```

Созданный документ должен появиться в очереди, если по нему ещё не было успешной генерации файла.

---

## 9. Сгенерировать файл

В меню выберите:

```text
Генерация документов
```

Найдите созданный документ через поиск.

Выберите формат результата:

```text
PDF
```

По умолчанию используется PDF.

При необходимости можно выбрать:

```text
DOCX
```

Папка сохранения по умолчанию:

```text
generated_documents
```

Файл будет сохранён по структуре:

```text
generated_documents/<сокращённое юрлицо>/<тип документа>/<имя файла>
```

Пример:

```text
generated_documents/ССК/Договоры/Договор ССК-260529-1 (ТЛК).pdf
```

Нажмите:

```text
Сгенерировать файл
```

Ожидаемый результат:

```text
Файл успешно сгенерирован
```

Система:

* берёт активный DOCX-шаблон;
* подставляет данные из PostgreSQL;
* создаёт DOCX или PDF;
* при PDF временный DOCX удаляется после успешной конвертации;
* записывает результат в `core.document_generation_log`.

---

## 10. Проверить реестр документов

В меню выберите:

```text
Реестр документов
```

Найдите созданный документ через поиск.

Проверьте:

* номер документа;
* тип документа;
* контрагента;
* текущий статус;
* статус генерации;
* имя файла;
* путь к файлу.

---

## 11. Обновить статус документа

В меню выберите:

```text
Обновление статуса
```

Найдите документ через поиск.

Выберите новый статус, например:

```text
SENT
```

Выберите канал доставки, например:

```text
EDO
```

Нажмите:

```text
Обновить статус
```

Ожидаемый результат:

```text
Статус обновлён
```

Статусы не перезаписываются. Каждое изменение добавляется новой строкой в историю:

```text
core.document_status_history
```

---

## 12. Проверить итоговый реестр

Вернитесь в:

```text
Реестр документов
```

Проверьте, что текущий статус документа изменился.

---

## 13. Дополнительный сценарий: дополнительное соглашение

После создания договора можно создать производный документ.

В меню выберите:

```text
Создание документа
```

Выберите того же контрагента и тип:

```text
ADDITIONAL_AGREEMENT
```

Выберите родительский договор.

Нажмите:

```text
Создать документ
```

Ожидаемый формат номера:

```text
<номер договора>-ДС-1
```

Пример:

```text
ССК-260529-1-ДС-1
```

---

## 14. Что демонстрирует проект

Demo-сценарий показывает:

* загрузку реквизитов из Excel;
* staging-слой;
* валидацию данных;
* импорт в нормализованную core-модель;
* проверку полноты реквизитов;
* создание договорных документов;
* автоматическую нумерацию;
* генерацию DOCX/PDF;
* хранение файлов по структуре папок;
* историю статусов;
* реестр документов;
* mart-витрины для интерфейса.

---

## 15. Ограничения demo-версии

Demo-версия является локальным MVP.

На текущем этапе:

* нет полноценной авторизации по паролю;
* выбор пользователя в интерфейсе сделан для демонстрации workflow;
* PDF-генерация использует Microsoft Word через `docx2pdf`;
* demo-данные обезличены и не являются реальными реквизитами;
* проект рассчитан на локальный запуск.

Планируемые улучшения:

* авторизация и роли пользователей;
* ограничение действий по ролям;
* расширенное управление архивными документами;
* добавление поля “основной способ подписания документа” отдельно от канала конкретного статусного события;
* расширенная генерация всех типов документов;
* настройка базовой папки сохранения через параметры приложения.
