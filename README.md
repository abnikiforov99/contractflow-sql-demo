# ContractFlow SQL

ContractFlow SQL — demo-проект внутренней системы для работы с договорными документами.

Проект показывает, как можно заменить ручной процесс подготовки договоров на связку:

```text
Excel - PostgreSQL - Streamlit - DOCX/PDF - Реестр документов
```

Система позволяет загружать реквизиты контрагентов из Excel, валидировать данные, импортировать их в нормализованную модель PostgreSQL, создавать договорные документы, генерировать DOCX/PDF-файлы и отслеживать статусы документооборота.

---

## Цель проекта

Проект был сделан как MVP внутреннего инструмента для автоматизации договорного процесса.

Основные задачи:

* убрать ручное копирование реквизитов из Excel в Word;
* снизить риск ошибок в реквизитах;
* хранить контрагентов и документы в нормализованной базе;
* фиксировать историю статусов документов;
* генерировать договорные документы по DOCX-шаблонам;
* дать пользователю простой интерфейс на Streamlit.

---

## Основной workflow

```text
1. Пользователь загружает Excel-файл с реквизитами контрагента
2. Данные попадают в staging-слой
3. SQL-функция выполняет валидацию
4. Ошибки и предупреждения отображаются в Streamlit
5. Валидные данные импортируются в core-слой
6. Пользователь создаёт договорный документ
7. Система генерирует номер документа
8. Пользователь генерирует DOCX/PDF по шаблону
9. Система сохраняет файл и пишет лог генерации
10. Пользователь обновляет статус документа
11. Реестр показывает текущее состояние документов
```

## Что реализовано

### База данных

* схемы `stg`, `core`, `audit`, `mart`;
* нормализованная модель контрагентов;
* модель договорных документов;
* история статусов;
* лог генерации документов;
* справочники типов документов, статусов и каналов;
* mart-витрины для интерфейса.

### Валидация

* проверка обязательных полей;
* проверка ИНН, КПП, ОГРН, ОГРНИП;
* отдельная логика для юрлиц и ИП;
* проверка банковских реквизитов;
* поддержка `ERROR` и `WARNING`;
* запрет импорта при критических ошибках.

### Streamlit-интерфейс

* выбор пользователя;
* загрузка Excel-реквизитов;
* валидация и импорт;
* просмотр полноты контрагентов;
* создание договорного документа;
* очередь генерации;
* генерация DOCX/PDF;
* обновление статуса;
* реестр документов;
* поиск по контрагентам и документам.

### Генерация документов

* DOCX-шаблоны с плейсхолдерами;
* подстановка данных через `docxtpl`;
* выбор формата результата: PDF или DOCX;
* PDF выбран по умолчанию;
* PDF-конвертация через `docx2pdf`;
* временный DOCX удаляется после успешной PDF-конвертации;
* файлы сохраняются в структуру:

```text
generated_documents/<юрлицо>/<тип документа>/<имя файла>
```

Пример:

```text
generated_documents/ССК/Договоры/Договор ССК-260529-1 (ТЛК).pdf
```

## Быстрый запуск

### 1. Создать PostgreSQL-базу

```sql
CREATE DATABASE contractflow_demo;
```

Подключиться к базе `contractflow_demo`.

---

### 2. Выполнить SQL-скрипты

Запустить скрипты по порядку:

```text
01_ddl
02_seed
03_staging
04_transform
05_mart
```

Подробный порядок запуска описан в файле:

```text
07_docs/run_order.md
```

---

### 3. Настроить подключение Streamlit

Создать файл:

```text
06_app/.streamlit/secrets.toml
```

На основе примера:

```text
06_app/.streamlit/secrets.example.toml
```

Пример:

```toml
[connections.contractflow_db]
url = "postgresql+psycopg2://postgres:YOUR_PASSWORD@localhost:5432/contractflow_demo"
```

Файл `secrets.toml` не должен попадать в GitHub.

---

### 4. Установить зависимости

Перейти в папку приложения:

```powershell
cd 06_app
```

Создать виртуальное окружение:

```powershell
python -m venv .venv
```

Активировать окружение.

PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

cmd:

```cmd
.venv\Scripts\activate.bat
```

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

---

### 5. Запустить Streamlit

```powershell
python -m streamlit run app.py
```

Открыть в браузере:

```text
http://localhost:8501
```

## Ограничения MVP

Demo-версия является локальным MVP.

На текущем этапе:

* нет полноценной авторизации по паролю;
* выбор пользователя работает без верификации;
* нет ролевого ограничения действий;
* PDF-конвертация зависит от установленного Microsoft Word;
* demo-данные обезличены;
* проект рассчитан на локальный запуск.
